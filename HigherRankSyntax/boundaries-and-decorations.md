# Decorated telescopes

This note defines a way of specifying the signature of a type theory. The
specification of a symbol records three things: how many arguments the symbol
takes, how many variables each argument binds, and what the type of the symbol
and of each of its arguments is. The first two are handled by a *carrier*
(§1), which fixes a language of shapes; the third by a *decoration* (§6), which
attaches to every argument position an expression naming its type.

Sections 1–7 are definitions, with a single running carrier. Sections 8 and 9
work two examples in full: Martin-Löf dependent sums and W-types. Section 10
gives the algebraic structure of decorations, and §11 uses it to assemble the
signature of dependent sums one declaration at a time. Section 12 says exactly
what a decoration does and does not constrain.

Everything below is formalised in Lean 4; §13 gives the correspondence.

---

## 1. Arities and slots

**Definition 1.1.** A *carrier* consists of

1. a monoid `𝔸`, whose elements are called **arities**, with multiplication
   written `Γ ⋈ Δ` and unit written `1`;
2. for each pair of arities `Γ` and `Δ`, a set `Γ ∋ Δ`, whose elements are
   called the **slots of `Γ` with binding arity `Δ`**, each such set carrying a
   well-order;

subject to:

3. `1 ∋ Δ` is empty for every `Δ`;
4. for each `Δ`, the slots of a product are the ordered sum of the slots of the
   factors: there is an order isomorphism
   `(Γ ∋ Δ) + (Γ' ∋ Δ) ≅ (Γ ⋈ Γ' ∋ Δ)`, whose two injections are written
   `inl` and `inr`, and in which every element of the left summand precedes
   every element of the right summand;
5. the relation "`Δ` is the binding arity of some slot of `Γ`" is well founded.

An arity is to be thought of as a list of declarations, and a slot `x : Γ ∋ Δ`
as one declaration in that list, `Δ` recording the arguments that the declared
symbol binds. Clause 5 says that a symbol's arguments are strictly simpler than
the symbol, which is what makes recursion on arities legitimate.

**Example 1.2 (the list carrier).** Define a set `E` of **entries** as the
least set such that `mk ℓ ∈ E` for every finite list `ℓ` of entries; that is,
`E` is the set of finite trees. Write `⟨e₁,…,eₙ⟩` for `mk [e₁,…,eₙ]`, so
`⟨⟩` is the tree with no subtrees.

Take `𝔸` to be the set of finite lists of entries, `Γ ⋈ Δ` concatenation, `1`
the empty list. Take `Γ ∋ Δ` to be the set of positions `i` of the list `Γ`
such that the entry at position `i` is `mk Δ`, ordered by position. Clauses
3–5 hold; clause 5 because `mk Δ` is a strictly larger tree than any entry of
`Δ`.

This is the carrier used in every example below. We write an arity as a list
and refer to its slots by position, counting from `0`.

**Definition 1.3 (rank).** The *rank* of an entry `mk [e₁,…,eₙ]` is `0` if
`n = 0`, and otherwise `1 + max(rank e₁, …, rank eₙ)`. A slot has the rank of
its entry. So a rank-`0` slot binds nothing, a rank-`1` slot binds only
rank-`0` slots, and so on.

Two entries recur below, and we name them:

```
nil := ⟨⟩          a symbol with no arguments
un  := ⟨nil⟩       a symbol with one argument, that argument binding nothing
```

`nil` has rank `0` and `un` has rank `1`.

## 2. Expressions

**Definition 2.1.** For each arity `Γ`, the set `Expr Γ` of **expressions over
`Γ`** is generated by the single rule

```
        x : Γ ∋ Δ        args : for each slot y : Δ ∋ Λ, an element of Expr (Γ ⋈ Λ)
       ───────────────────────────────────────────────────────────────────────────
                                  ap x args ∈ Expr Γ
```

So an expression is a slot of `Γ` — its **head** — applied to one argument for
each slot of the head's binding arity. The argument supplied for the slot `y`
is an expression over `Γ` extended by `Λ`, the binding arity of `y`: the slots
of `Λ` are the variables that `y` binds, and they are available in that
argument and nowhere else.

The definition is by recursion on `Γ`'s slots' binding arities, which
terminates by 1.1(5).

**Notation 2.2.** Let `x : Γ ∋ Δ` and let `y₁, …, yₙ` be the slots of `Δ` in
order. We write

```
x(e₁, …, eₙ)
```

for the expression `ap x args` in which `args` assigns `eᵢ` to `yᵢ`. When
`n = 0` we write just `x`. This is the notation used in all later examples: so
`tm A` is the slot `tm` applied to the single argument `A`, and `fst A B p` is
the slot `fst` applied to its three arguments in order.

**Remark 2.3.** `Expr 1` is empty: by 1.1(3) the arity `1` has no slots, so
there is no possible head.

## 3. Precedence

A declaration may mention the declarations before it, so an arity must be able
to say which part of itself precedes a given slot. That is not determined by
1.1, and is added as further structure.

**Definition 3.1.** A *precedence* on a carrier assigns to each slot
`x : Γ ∋ Δ` two arities `before(x)` and `after(x)` such that

```
before(x) ⋈ after(x) = Γ
```

with `x` lying in the second factor under the isomorphism 1.1(4), compatibly
with `inl` and `inr`, and so that a slot precedes `x` in the order of 1.1(2) if
and only if it lies in `before(x)`.

**Example 3.2.** For the list carrier: `before(i)` is the initial segment of
the list strictly before position `i`, and `after(i)` is the remaining segment,
beginning at `i`.

## 4. Slot paths

A decoration must supply a type not only for each declared symbol but also for
each *argument* of each symbol — in `Σ : [A : ty, B : […] ty] ty` both `A` and
`B` need types — and an argument may itself have arguments, to any depth. So we
need names for the slots reachable from an arity by descending into binding
arities. That is what a slot path is.

**Definition 4.1.** For arities `Γ`, `Φ`, `Δ`, the set `SlotPath Γ Φ Δ` is
generated by

```
    x : Γ ∋ Δ
  ─────────────────────────────────
  here x ∈ SlotPath Γ (before x) Δ

    x : Γ ∋ β        p ∈ SlotPath β Φ Δ
  ────────────────────────────────────────────
  nested x p ∈ SlotPath Γ (before x ⋈ Φ) Δ
```

An element of `SlotPath Γ Φ Δ` is a route from `Γ` to a slot obtained by
descending zero or more times into a binding arity. The three indices are:
`Γ`, the arity descended from; `Δ`, the binding arity of the slot arrived at;
and `Φ`, the product of the `before`s collected at each step of the descent.

**Example 4.2.** Let `Γ = [nil, un]`, using the entries of 1.3. There are three slot paths in
`Γ`:

| path | slot reached | `Φ` | `Δ` |
|---|---|---|---|
| `here 0` | the entry `nil` at position `0` | `1` | `1` |
| `here 1` | the entry `un` at position `1` | `[nil]` | `[nil]` |
| `nested 1 (here 0)` | the single slot of `un`'s binding arity | `[nil] ⋈ 1 = [nil]` | `1` |

For the last row: `before(1) = [nil]` in `Γ`, and the slot descended to is at
position `0` of `[nil]`, where `before(0) = 1`.

**Remark 4.3.** `SlotPath 1 Φ Δ` is empty, since `1` has no slots.

## 5. Boundaries

In an ordinary many-sorted signature one fixes in advance a set of sorts, and
each symbol is declared at one of them. Here we do not fix such a set: a sort
is a declared symbol like any other, and the type of an object is an
*expression* — typically a sort symbol applied to arguments, as in `tm A` or
`Hom(x, y)`.

**Definition 5.1.** A **boundary over `Ω`** is either the token `sort`, or
`of S` for an expression `S ∈ Expr Ω`. We write `Bd(Ω)` for the set of
boundaries over `Ω`.

**Definition 5.2.** A slot whose boundary is `sort` is a **sort slot**; a slot
whose boundary is `of S` is an **object slot of sort `S`**.

**Example 5.3.** In §8 the symbol `ty` is declared with boundary `sort`, and
the symbol `Σ` with boundary `of ty`, where `ty` is the expression consisting
of the head `ty` applied to no arguments. So `ty` is a sort slot and `Σ` is an
object slot, of the sort named by the expression `ty`.

**Remark 5.4.** By 2.3 a boundary over the arity `1` can only be `sort`, there
being no expressions over `1` at all. This is why the first symbol of a
signature is necessarily a sort.

## 6. Decorations

**Definition 6.1.** Let `Ω` and `Γ` be arities. A **decoration of `Γ` over the
base `Ω`** is a function `D` assigning to every slot path
`p ∈ SlotPath Γ Φ Δ`, for all `Φ` and `Δ`, a boundary

```
D(p) ∈ Bd(Ω ⋈ Φ ⋈ Δ).
```

The arity over which `D(p)` is taken has three factors:

- `Ω`, the base: the symbols declared before `Γ` begins;
- `Φ`, supplied by the path: the parts of `Γ`, and of each binding arity
  descended through, preceding the slot reached;
- `Δ`: the slots of the binding arity of the slot reached — that is, the
  variables that slot binds.

**Definition 6.2.** A **decorated telescope over `Ω`** is a pair `(Γ, D)` with
`Γ` an arity and `D` a decoration of `Γ` over `Ω`. We call `Γ` its *underlying
arity*. A **theory** is a decorated telescope over the base `1`.

**Example 6.3.** Continuing 4.2, a decoration of `Γ = [nil, un]` over the base
`1` consists of three boundaries, one per row of the table in 4.2:

```
D(here 0)            ∈ Bd(1 ⋈ 1 ⋈ 1)         = Bd(1)
D(here 1)            ∈ Bd(1 ⋈ [nil] ⋈ [nil]) = Bd([nil, nil])
D(nested 1 (here 0)) ∈ Bd(1 ⋈ [nil] ⋈ 1)     = Bd([nil])
```

Name the slot at position `0` of `Γ` by `c`, the slot at position `1` by `f`,
and the single slot of `f`'s binding arity by `x`. The arities the three
boundaries are taken over are then

- `1`, the empty arity: by 5.4 the boundary can only be `sort`;
- `[c, x]`: the `Φ` factor contributes `c`, being `before(1)`, and the `Δ`
  factor contributes `x`, the variable `f` binds. The expressions over it are
  `c` and `x`;
- `[c]`: the `Φ` factor of the path `nested 1 (here 0)` is
  `before(1) ⋈ before(0) = [c] ⋈ 1`, and the slot descended to binds nothing,
  so `Δ = 1`. The only expression over it is `c`.

Taking

```
D(here 0)            = sort
D(here 1)            = sort
D(nested 1 (here 0)) = of c
```

makes `c` a sort, `f` a sort, and the argument of `f` an object of sort `c`:
that is, a sort `c` together with a family of sorts indexed by objects of `c`.
In the notation of 7.1 this reads

```
c : [ ]        sort
f : [ x : c ]  sort
```

and it is the two-symbol fragment `ty`, `tm` of §8. Taking `D(here 1) = of c`
instead would make `f` not a sort but an operation on `c`.

## 7. Notation for declarations

Decorations are displayed in a linear notation, which we now fix.

**Notation 7.1.** A decorated telescope over `Ω` whose underlying arity has
slots `x₁,…,xₙ` in order is written as a list of lines

```
name₁ : [ … ]  b₁
   ⋮
nameₙ : [ … ]  bₙ
```

where on the line for `xᵢ`:

- `nameᵢ` is a chosen name for `xᵢ`, used to refer to it in later expressions;
- the bracketed list is the display, in the same notation applied recursively,
  of the decorated telescope formed by `xᵢ`'s binding arity together with the
  boundaries that `D` assigns to paths through `xᵢ`; it is written `[ ]` when
  that arity is `1`;
- `bᵢ` is `D(here xᵢ)`, written `sort` if it is the token `sort`, and written
  as the bare expression `S` if it is `of S`.

Inside an expression, a name refers to the slot it was given to. So the
notation is a way of writing a decoration, and nothing else; §8 decodes an
instance of it completely.

## 8. Example: dependent sums

The theory of dependent sums (without equations) is displayed as

```
ty   : [ ]                                                     sort
tm   : [ A : ty ]                                              sort
Σ    : [ A : ty, B : [x : tm A] ty ]                           ty
pair : [ A : ty, B : [x : tm A] ty, a : tm A, b : tm (B a) ]   tm (Σ A B)
fst  : [ A : ty, B : [x : tm A] ty, p : tm (Σ A B) ]           tm A
snd  : [ A : ty, B : [x : tm A] ty, p : tm (Σ A B) ]           tm (B (fst A B p))
```

We decode this into a theory in the sense of 6.2.

### 8.1 The underlying arity

Delete from a line every name and every boundary; what is left is its bracket
structure, a nesting of brackets and commas. Read it as an arity: a bracketed
list of `n` items is `⟨e₁,…,eₙ⟩`, where `eᵢ` is the reading of the `i`-th item,
and an item that carries no bracket is `⟨⟩`. For the line of `Σ`:

```
Σ : [ A : ty, B : [x : tm A] ty ]  ty     the line
    [       ,        [      ]    ]        bracket structure: two items, the second bracketed
    ⟨  ⟨⟩   ,        ⟨  ⟨⟩  ⟩    ⟩        read as an arity
```

so `Σ = ⟨⟨⟩, ⟨⟨⟩⟩⟩`. Doing this to each line, and using the abbreviations of
1.3:

```
ty   = ⟨⟩                      = nil
tm   = ⟨nil⟩                   = un
Σ    = ⟨nil, un⟩
pair = ⟨nil, un, nil, nil⟩
fst  = ⟨nil, un, nil⟩
snd  = ⟨nil, un, nil⟩
```

`ty` has no arguments; `tm` has one argument binding nothing; `Σ` has two
arguments, the first binding nothing and the second binding one variable; and
so on. The underlying arity of the theory is the six-entry list

```
Θ = [ty, tm, Σ, pair, fst, snd].
```

By 1.3, `Σ` has rank `2`: its argument `B` has rank `1`, because `B` binds the
rank-`0` slot `x`.

### 8.2 The decoration on immediate slots

For the immediate slot at position `i`, the path is `here i`, so
`Φ = before(i)` is the list of the first `i` entries and `Δ` is that entry's
binding arity. The boundary is taken over `1 ⋈ Φ ⋈ Δ = Φ ⋈ Δ`.

| slot | `Φ = before` | `Δ` | boundary is over | value |
|---|---|---|---|---|
| `ty` (0) | `[]` | `[]` | `[]` | `sort` |
| `tm` (1) | `[ty]` | `[nil]` | `[ty, nil]` | `sort` |
| `Σ` (2) | `[ty, tm]` | `[nil, un]` | `[ty, tm, nil, un]` | `of ty` |
| `pair` (3) | `[ty, tm, Σ]` | `[nil, un, nil, nil]` | `[ty, tm, Σ, nil, un, nil, nil]` | `of (tm (Σ A B))` |
| `fst` (4) | `[ty, tm, Σ, pair]` | `[nil, un, nil]` | `[ty, tm, Σ, pair, nil, un, nil]` | `of (tm A)` |
| `snd` (5) | `[ty, tm, Σ, pair, fst]` | `[nil, un, nil]` | `[ty, tm, Σ, pair, fst, nil, un, nil]` | `of (tm (B (fst A B p)))` |

The `ty` row illustrates 5.4: the boundary is over the empty arity, so `sort`
is the only possibility.

### 8.3 The boundary of `snd`, in full

Take the last row. The arity over which the boundary is taken has eight
entries, at positions

```
0: ty     1: tm     2: Σ     3: pair     4: fst     5: A     6: B     7: p
```

where positions `0`–`4` come from `Φ` (the symbols declared before `snd`) and
positions `5`–`7` from `Δ` (the arguments of `snd`, named `A`, `B`, `p` by
7.1). The expression `tm (B (fst A B p))` denotes

- `fst A B p`: head the slot at position `4`, whose binding arity is
  `[nil, un, nil]`, so three arguments are required. The first, for a slot of
  binding arity `1`, is an expression over the same eight-entry arity: the slot
  at position `5`, applied to nothing, that is `A`. The second, for a slot of
  binding arity `[nil]`, is an expression over that arity extended by one
  entry, in which the bound variable occupies position `8`: it is the slot at
  position `6` applied to the slot at position `8`, that is `B x`. The third is
  the slot at position `7`, that is `p`.
- `tm (…)`: head the slot at position `1`, whose binding arity is `[nil]`, so
  one argument, namely the previous expression.

This boundary uses all three factors of 6.1: `tm` and `fst` come from `Ω ⋈ Φ`,
the arguments `A`, `B`, `p` come from `Δ`, and the variable at position `8`
comes from the binding arity of `fst`'s second argument, which is available
only inside that argument.

### 8.4 The decoration on nested slots

The remaining slot paths descend into a binding arity. For `Σ`, whose binding
arity is `[nil, un]` with slots `A` at position `0` and `B` at position `1`:

| path | `Φ` | `Δ` | boundary is over | value |
|---|---|---|---|---|
| `nested Σ (here A)` | `[ty,tm] ⋈ [] = [ty,tm]` | `[]` | `[ty, tm]` | `of ty` |
| `nested Σ (here B)` | `[ty,tm] ⋈ [nil] = [ty,tm,nil]` | `[nil]` | `[ty, tm, nil, nil]` | `of ty` |
| `nested Σ (nested B (here x))` | `[ty,tm] ⋈ ([nil] ⋈ []) = [ty,tm,nil]` | `[]` | `[ty, tm, nil]` | `of (tm A)` |

The last row is the line `B : [x : tm A] ty` of the display: `x` is the slot of
`B`'s binding arity, its boundary is taken over the three-entry arity
`[ty, tm, A]`, and the expression `tm A` is the slot at position `1` applied to
the slot at position `2`. That `A` is available at all is because `Φ` collected
`before(B) = [nil]`, the segment of `Σ`'s binding arity preceding `B`.

The paths through `tm`, `pair`, `fst` and `snd` are read off in the same way.

## 9. Example: W-types

```
W   : [ A : ty, B : [x : tm A] ty ]                             ty
sup : [ A : ty, B : [x : tm A] ty,
        a : tm A,
        f : [y : tm (B a)] tm (W A B) ]                         tm (W A B)
```

declared after `ty` and `tm` as in §8. Their entries are

```
W   = ⟨nil, un⟩
sup = ⟨nil, un, nil, un⟩
```

so both have rank `2`, by the same reckoning as in 8.1: the arguments `B` and
`f` have rank `1`.

Three features not present in §8 appear here.

**The bound variable's type depends on an earlier argument.** In `f`'s binding
arity, the slot `y` has boundary `of (tm (B a))`. Its path is
`nested sup (nested f (here y))`, and for it

```
Φ = before(sup) ⋈ ( before(f) ⋈ before(y) )
  = [ty, tm, W] ⋈ ( [nil, un, nil] ⋈ [] )
  = [ty, tm, W, nil, un, nil]
```

with positions `3`, `4`, `5` being `A`, `B`, `a`. The expression `tm (B a)` is
the slot at position `1` applied to the expression `B a`, which is the slot at
position `4` applied to the slot at position `5`. So `y`'s type mentions two of
`sup`'s earlier arguments, and it can because `Φ` collected `before(f)`, which
contains them.

**A symbol's boundary mentions a variable bound by one of its own arguments —
or, here, does not.** The boundary of `sup` is `tm (W A B)`, over the arity

```
[ty, tm, W, nil, un, nil, un]
```

with `A`, `B`, `a`, `f` at positions `3`–`6`. Here `f` occurs in no expression,
but `B` does: the argument of `W` at position `4` has binding arity `[nil]`, so
it is supplied by an expression over the arity extended by one entry, and that
expression is the slot at position `4` applied to the fresh slot at position
`7`, that is `B x`. Compare 8.3, where `snd`'s boundary does mention such a
fresh slot, at position `8`.

**An argument that binds an argument that binds.** The eliminator, declared
after `sup`, is

```
elim : [ A : ty,
         B : [x : tm A] ty,
         C : [z : tm (W A B)] ty,
         e : [ a : tm A,
               f : [y : tm (B a)] tm (W A B),
               g : [y : tm (B a)] tm (C (f y)) ]   tm (C (sup A B a f)),
         w : tm (W A B) ]                                     tm (C w)
```

Its entry is

```
elim = ⟨nil, un, un, ⟨nil, un, un⟩, nil⟩
```

the fourth component being the entry of `e`, which has rank `2` because its
arguments `f` and `g` have rank `1`. So `elim` has rank `3`.

The boundary of `g` shows both a `Φ` and a `Δ` contribution at a path of
length three. Its path is `nested elim (nested e (here g))`, and

```
Φ = before(elim) ⋈ ( before(e) ⋈ before(g) )
  = [ty, tm, W, sup] ⋈ ( [nil, un, un] ⋈ [nil, un] )
  = [ty, tm, W, sup, nil, un, un, nil, un]
```

with positions `4`–`8` being `A`, `B`, `C`, `a`, `f`, while `Δ = [nil]` is `g`'s
own binding arity, contributing `y` at position `9`. The boundary
`of (tm (C (f y)))` is the slot at position `1` applied to the slot at position
`6` applied to the slot at position `8` applied to the slot at position `9`: it
mentions `f`, a sibling argument of `e` collected by `before(g)`, and `y`, the
variable `g` itself binds.

## 10. Substitution, and the algebra of decorations

### 10.1 Substitution

**Definition 10.1.** A **substitution** `σ : Γ ⇒ Δ` assigns to each slot
`x : Γ ∋ Λ` an expression `σ(x) ∈ Expr (Δ ⋈ Λ)`. It is applied to an expression
over `Γ` by replacing each head `x` by `σ(x)`, with the arguments of that head
substituted for the slots of `Λ`.

Each slot `x : Γ ∋ Λ` determines an expression over `Γ ⋈ Λ`, namely `x` applied
to the slots of `Λ`; assigning that to `x` gives the identity substitution.
Substitutions compose. So arities and substitutions form a category, which we
write `𝕊`.

**Remark 10.2.** In categorical language, `Expr` together with the identity
substitution and the application of substitutions is a relative monad over the
functor sending an arity `Γ` to its family of slot sets, and `𝕊` is that
monad's Kleisli category. Nothing below depends on this description; it is
recorded because it identifies the structure in 10.3 and 10.5.

### 10.2 Decorations form a module

**Proposition 10.3.** Let `DTel(Ω)` be the set of decorated telescopes over
`Ω`. A substitution `σ : Ω ⇒ Ω'` acts on `DTel(Ω)` by replacing every boundary
`D(p) ∈ Bd(Ω ⋈ Φ ⋈ Δ)` by its image under `σ`, extended by the identity on `Φ`
and `Δ`; the underlying arity and the paths are unchanged. This makes `DTel` a
functor `𝕊 → Set`.

*Proof.* Functoriality is the corresponding statement for `Expr`, applied
boundary by boundary. ∎

A functor `𝕊 → Set` is called a **module** over the monad of 10.2, so 10.3
says: decorated telescopes form a module over the syntax monad.


### 10.3 The shape, and the tensor

**Definition 10.5.** By 10.3 the assignment `Ω ↦ DTel(Ω)` is a functor, and
sending a decorated telescope to its underlying arity is a natural
transformation from it to the constant functor at `𝔸`. A functor `𝕊 → Set`
equipped with such a natural transformation to the constant functor at `𝔸` is
called an **arity-shaped module**, and the transformation is its **shape**.

Arity-shaped modules carry the following product.

**Definition 10.6.** For arity-shaped modules `M` and `N`, their **tensor**
`M ⊗ N` is the arity-shaped module with

```
(M ⊗ N)(Ω) = { (m, n) : m ∈ M(Ω),  n ∈ N(Ω ⋈ shape(m)) }
```

and `shape(m, n) = shape(m) ⋈ shape(n)`. The unit `I` has `I(Ω)` a one-element
set of shape `1`.

The second component is taken over a base extended by the shape of the first;
this is what distinguishes `⊗` from the pointwise product of functors. With
the evident associativity and unit isomorphisms, `⊗` makes arity-shaped modules
a monoidal category.

### 10.4 Decorated telescopes form a monoid object

**Definition 10.7 (concatenation).** Let `(Γ, D)` be a decorated telescope over
`Ω` and `(Γ', D')` a decorated telescope over `Ω ⋈ Γ`. Their **concatenation**
is the decorated telescope over `Ω` with underlying arity `Γ ⋈ Γ'` and with
decoration assigning to a slot path of `Γ ⋈ Γ'` the boundary given by `D` if
the path descends from a slot of `Γ`, and by `D'` if it descends from a slot of
`Γ'`.

That this is well defined uses 1.1(4), which splits a slot of `Γ ⋈ Γ'` into one
of `Γ` or one of `Γ'`, and the compatibility of `before` with that splitting
required by 3.1, which is what makes the `Φ` index of the two cases agree.

**Definition 10.8.** The **empty** decorated telescope over `Ω` has underlying
arity `1`; by 4.3 there are no slot paths, so there is nothing to decorate.

**Theorem 10.9.** Concatenation and the empty decorated telescope make `DTel` a
monoid object in the monoidal category of 10.6: concatenation is associative,
and the empty telescope is a two-sided unit.

*Proof.* Both sides of each law have the same underlying arity by associativity
and unitality of `𝔸`, and assign the same boundary to each slot path, by
1.1(4) and 3.1. ∎

## 11. Building the signature one declaration at a time

Definition 10.7 requires the second telescope to be given over the base `Ω`
extended by the underlying arity of the first. That is exactly the condition
under which the second may mention the symbols of the first. So a signature can
be built by declaring one symbol at a time, and Theorem 10.9 says that the
result does not depend on how the declarations are grouped.

For §8, take the six one-slot decorated telescopes

```
Tᵗʸ    over  1                            ty   : [ ]                       sort
Tᵗᵐ    over  [ty]                         tm   : [ A : ty ]                sort
Tˢ     over  [ty, tm]                     Σ    : [ A : ty, B : […] ty ]    ty
Tᵖ     over  [ty, tm, Σ]                  pair : […]                       tm (Σ A B)
Tᶠ     over  [ty, tm, Σ, pair]            fst  : […]                       tm A
Tˢⁿ    over  [ty, tm, Σ, pair, fst]       snd  : […]                       tm (B (fst A B p))
```

Each is over precisely the arity listed to its left, and its boundaries are
expressions over that arity extended as in 6.1. Concatenating them,

```
Tᵗʸ · Tᵗᵐ · Tˢ · Tᵖ · Tᶠ · Tˢⁿ,
```

is a decorated telescope over `1`, that is a theory, and its underlying arity
is `Θ` of 8.1.

The same operation applies one level down. The binding arity of `Σ` with its
decoration — the bracketed part of the third line — is the concatenation of

```
A : ty                over  [ty, tm]
B : [x : tm A] ty     over  [ty, tm, A]
```

and the base of the second segment is what makes the occurrence of `A` in
`x : tm A` meaningful.

## 12. What a decoration determines, and what it does not

By 6.1 a decoration is a function assigning boundaries to slot paths, and that
is all of the data. Three further conditions one might expect are not part of
it, and would have to be imposed by a separate layer of judgements, not defined
in this note.

**A boundary need not name a sort.** `Bd(Ω)` is 5.1 with no side condition, so
`of S` may be given for any expression `S`, including one whose head is an
object slot. In the theory of §8, declaring a seventh symbol

```
c : [ A : ty, B : [x : tm A] ty, p : tm (Σ A B) ]   fst A B p
```

satisfies 6.1: the boundary is `of S` for the expression `S = fst A B p` over
the arity of 8.2's last row. But the head of `S` is `fst`, which 8.2 declares
with boundary `of (tm A)`, so `fst` is an object slot and not a sort slot.

**The arguments supplied to a sort need not match its declaration.** In §8,
`tm` is declared with one argument, whose boundary is `ty` by 8.4. Over an
arity containing `ty`, `tm` and a slot `A`, the expression `tm (tm A)` is
nonetheless well formed by 2.1: `tm` takes exactly one argument, and `tm A` is
an expression. That the argument supplied is itself an application of `tm`,
rather than something declared with boundary `ty`, is not a condition imposed
by 2.1.

Two conditions *are* imposed by §§1–7.

**Arities are respected.** By 2.1 an application supplies one argument for each
slot of its head's binding arity; there is no expression applying a symbol to
the wrong number of arguments.

**Scope is respected.** By 6.1 the boundary at a path lies over
`Ω ⋈ Φ ⋈ Δ`, and by 4.1 the index `Φ` collects only `before`s. So a boundary
cannot mention a symbol declared after the slot it decorates: the arity over
which it is written does not contain that symbol.

**Remark 12.1.** The third condition above is deliberate rather than an
oversight. In §8 the boundary of `snd` is the expression
`tm (B (fst A B p))`. A theory of dependent sums also asserts the equation
`fst A B (pair A B a b) = a`, and with it the boundary of `snd` applied to
`pair A B a b` should be usable as `tm (B a)`. The expressions
`tm (B (fst A B (pair A B a b)))` and `tm (B a)` are distinct elements of
`Expr`, and must be, since `Expr` is generated freely by 2.1. They become equal
only in a quotient of `Expr` by the equations of the theory. Imposing at the
level of 6.1 that a boundary be "the" type of its slot would therefore be
imposing a condition that the equations of the theory are supposed to establish.
